# Исправления после аудита — 28 октября 2026

Изменения сделаны локально по запросу «исправь что нужно». Production, внешние API, DNS и чужие сервисы не изменялись. Существовавшие изменения интерфейса сохранены. Коммит, push и deploy не выполнялись.

## Что исправлено

- **Миграции:** initial schema заморожена и больше не импортирует текущие модели. Все 8 миграций проходят на пустой PostgreSQL. Согласованы индексы ORM и миграций, включая уникальность открытого нарушения. Исправлено удаление PostgreSQL enum при полном откате.
- **История сделок:** новая миграция `0008` разрешает A → B → A; одинаковый повтор текущего payload по-прежнему не создаёт snapshot. Изменения полей из NULL теперь попадают в события.
- **Sync:** advisory lock держится отдельным соединением до завершения фазы. DB-ошибки строк изолированы savepoint; ошибка фазы сохраняется отдельно. Cursor берётся в начале загрузки, сохраняет timezone, не двигается при ошибке. Страницы запрашиваются с ID ASC; некорректный ответ списка или нерастущая пагинация завершаются ошибкой, а не выглядят как пустая успешная выгрузка.
- **Activities:** обе загрузки ограничены владельцами из активной локальной области синхронизации; полная успешная сверка удаляет исчезнувшие записи локального кэша. Пустая delta также обновляет временные флаги всех сделок. Ближайшая будущая задача не скрывается просроченной. Одна некорректная строка не отравляет транзакцию следующих строк.
- **Worker:** успех требует всех трёх CRM-фаз. Timeman и оценка рабочего дня запускаются даже при исключении CRM. Bootstrap использует тот же защищённый путь. Оценки Sales Rules и рабочего дня сериализованы транзакционными блокировками PostgreSQL.
- **Свежесть:** используется самая старая подтверждённая отметка обязательных фаз; свежий справочник или доступность Bitrix не маскируют старые сделки/задачи.
- **Manager Control:** ротация batch-опроса охватывает менеджеров за пределами первых 50. Время наблюдения фиксируется для каждого ответа, записи изолированы savepoint. Реально применяется первичный `UF_DEPARTMENT`, после персонального назначения и перед общим графиком.
- **Нарушения рабочего дня:** snapshot берётся только за нужную дату. Без наблюдения возвращается UNKNOWN, а не «не начал день». Оценка ограничена временем последнего наблюдения; утренний snapshot не доказывает незакрытие вечером. Неизвестный статус не доказывает ни нарушение, ни его устранение. Без утверждённой даты контроля всё остаётся preview.
- **GET:** чтение roster и policy больше не создаёт записи. Для сохранения policy используется защищённый PATCH; roster обновляется коллектором или явным изменением администратора.
- **Отчёты:** отсутствие измерений — `fact_seconds=null`, «Нет данных», а не ноль. Delta не рассчитывается при неполном охвате рабочих дней. Preview исключён из официальных итогов. План для будущих дней не создаёт текущий недобор. Конфигурация графиков, назначений, календаря и отсутствий загружается пакетно.
- **Валидация:** timezone, время, дни недели, неотрицательные пороги, последовательность дат; ночной график явно отклоняется как неподдерживаемый. Месяц вне 1–12 отклоняется; диапазон командного отчёта ограничен 93 днями. CSV формируется стандартным writer с экранированием формул в имени.
- **KPI:** просроченные задачи требуют существующей немissing сделки-владельца; stage changes и нарушения учитывают фильтры менеджера/воронки. Для stock-метрик убраны вымышленные исторические дельты. Текущая неделя/месяц сравниваются с сопоставимой прошедшей частью предыдущего периода. План выбирается только при точном совпадении периода и однозначной записи; общий план не переносится на выбранную воронку.
- **Интерфейс:** календарные типы согласованы с API; доступны время и норма сокращённого дня. Новый график не заполнен выдуманным регламентом и выключен по умолчанию. Исправлены подписи sales violations, нижнерегистровых CRM-полей и sync dictionaries; даты показываются в Europe/Moscow. Устранены предупреждения lint о зависимостях hooks.
- **Секреты:** `.env`, ключи и дампы исключены из backend/frontend build context; Docker entrypoint оставлен доступным. Backend и worker работают непривилегированным пользователем. Логи маскируют токены, пароли и URL credentials; исключения сохраняют тип/место без SQL-параметров. System не отдаёт сырой текст ошибок. В production введены проверки HTTPS origins, secure cookies, DEMO=false и пароля БД; настройки скрывают значения входа в ошибках валидации.
- **Подготовка выпуска:** отдельные Compose, nginx TLS, env example и [runbook](production-runbook.md). Скрипт [backup/restore](../ops/backup.py) не перезаписывает готовые копии и восстанавливает только в новую `focus_restore_*` БД. CI охватывает текущую и `codex/**` ветки; добавлены PostgreSQL 16 migrations/rollback/schema/regression gates.

## Что ещё не подтверждено или требует отдельной работы

**Это не разрешение на production deploy.**

1. Браузерный smoke/sidebar/mobile/E2E, Docker runtime, реальные TLS-сертификаты и live read-only Bitrix/Avito не проверены. Предыдущая автоматическая проверка разрешений отклонила старт frontend (`blocked by policy`); обхода или повторного запуска сервера не было. Sidebar/responsive имеют статус **UNKNOWN**, не «доказанно сломано».
2. Нужно получить утверждённые графики, регламент, планы и дату контроля. Существовавшие до исправления неверные настройки и исторические нарушения автоматически не удалялись: требуется сверка с реальными наблюдениями перед официальным использованием. Версионирование исторических графиков пока отсутствует.
3. Пагинация Bitrix всё ещё offset-based, хотя теперь упорядочена и cursor безопаснее. Поведение при одновременных удалениях/изменении доступности на живом портале требует проверки; это не транзакционный snapshot Bitrix.
4. Денежные агрегаты разных валют всё ещё не имеют FX-конверсии/полной валютной группировки. Нельзя использовать смешанные валюты как единую сумму; до запуска финансовых отчётов подтвердить единую валюту данных либо реализовать валютный контракт. Планы количества сделок, prorating и управление планами в UI не добавлялись.
5. Полные CRUD интерфейсы отсутствий/roster, Avito Analytics, timeline/comment sync, AI/calls и desktop idle/offline — отдельные функции, не реализованные этим исправлением.
6. Реальные backup schedule/retention/off-host storage, мониторинг worker и TLS renewal требуют настройки на выбранной инфраструктуре. Образы Docker, nginx runtime и deployment пока не проверены. Изменённые файлы ещё нужно сохранить в Git после просмотра.

Первичный [аудит](master-product-audit.md) и его JSON сохранены как свидетельство состояния **до** исправлений. Их старые FAIL не следует считать результатом повторной проверки текущего кода; актуальный локальный результат находится здесь.
